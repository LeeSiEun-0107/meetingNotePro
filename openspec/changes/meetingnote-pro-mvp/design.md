# Design

## Context

동기와 범위는 proposal.md 를 따른다. 구현 입력은 `docs/` 의 프로그램 정의 · 스토리보드 · 디자인 시스템과 확정 퍼블리싱 `publish/` 이다.

- 폴더: `backend/`(FastAPI) · `frontend/`(Vanilla JS) · 루트 `.env` · `.env.example` · `.gitignore`
- 스택은 문서가 고정한다: FastAPI, 로컬 SQLite, 배포 Neon Postgres, SQLAlchemy ORM, Tailwind CDN, Node.js 를 임의로 고르지 않는다
- 로컬은 FastAPI 가 `frontend/` 를 StaticFiles 로 같이 서빙한다 (`127.0.0.1:8000`, `/login.html` 처럼 확장자를 붙인 경로)
- 배포는 Vercel 한 프로젝트에 프런트와 백엔드를 함께 올린다 (`pyproject.toml` 의 `[tool.vercel]` entrypoint)
- 숫자 제약: 팀당 6명 · 동시 50명 · JWT 24h · 업로드 25MB · 받아쓰기 60초 · 댓글 500자 · 활동 50건 · API 100ms(받아쓰기와 인증 2종 제외) · 가입과 로그인 250ms · 목록 렌더 50ms

## Goals / Non-Goals

**Goals:**
- API 26개 · DB 7테이블 · 화면 6개 · 확인 상태 62개를 문서 그대로 구현한다
- 같은 스펙에서 실행마다 같은 결과가 나오게 문서에 적힌 값(오류 코드 · 응답 필드 · 정렬 · 띠 색)을 따른다

**Non-Goals:**
- 문서에 없는 필드 · 엔드포인트 · 오류 코드 · 활동 종류를 만들지 않는다
- 새 화면이나 새 색을 만들지 않는다 (스토리보드 밖 오류는 공통 알림으로만)
- 로그 수집 · Sentry · 마이크로서비스 분리 · 서버 측 토큰 차단 목록

## Decisions

### D1. 프런트는 `publish/` 를 옮겨 와 데이터만 실제 API 로 바꾼다
`publish/*.html` 과 `theme.js` 를 `frontend/` 로 가져오고 클래스 문자열은 한 글자도 바꾸지 않는다. 바꾸는 것은 세 가지뿐이다.
- 샘플 배열(`SAMPLE`, `ALL`, `MEMBERS` 등)과 `STATES` 객체를 `fetch` 호출과 렌더로 대체
- `stateBar` 호출과 `note` · API 경로를 적은 줄 제거 (퍼블리싱 확인용이라고 파일 안에 적혀 있다)
- 토스트의 개발자용 문구(`PUT 200`, `{assignee_id}`)를 사람이 읽는 문구로 교체

대안: 화면을 처음부터 다시 만든다. 지시(확정 디자인 그대로)와 어긋나므로 택하지 않는다.

### D2. 공통 호출 래퍼 하나로 토큰과 오류를 처리한다
모든 화면은 하나의 `api()` 함수로 호출한다. 이 함수가 `Authorization: Bearer` 를 붙이고, `{code, msg}` 오류를 풀며, 401 `TOKEN_EXPIRED` 를 받으면 토큰을 지우고 `/login.html` 로 보낸다. 스토리보드에 없는 오류(네트워크 · 500 · 403 · 구분 실패 · 받아쓰기 시간 초과)는 `window.notice("red", …)` 한 줄로 보여 준다. 새 색이나 새 화면은 없다.

### D3. 권한은 서버가 판정하고 화면은 그 결과로 그린다
- 서버: 모든 팀 API 에서 호출자가 그 팀의 멤버인지 먼저 보고(아니면 `FORBIDDEN` 403), owner 전용은 `OWNER_ONLY` 403, 회의록과 댓글은 쓴 사람 또는 owner 만이다
- 화면: 댓글은 응답의 `can_delete`, 내 정보 응답의 `role` 을 써서 owner 전용 조작을 잠근다. 회의록 수정과 삭제는 응답의 올린 사람 `author_id`(문서의 응답 필드에 없어 사용자 승인으로 추가한 유일한 필드)와 내 `id` · `role` 로 정한다
- 잠금은 숨기지 않고 비활성으로 보인다 (team.html 의 member 권한 상태와 같은 표시)

### D4. 세 항목 구분은 Gemini 한 번 호출로 한다
모델은 `.env` 의 `GEMINI_MODEL`, 키는 `GEMINI_API_KEY`(문서 기본값은 `gemini-3.1-flash-lite`). 받아쓰기와 세 항목 구분을 둘 다 이 공급자로 한다. 구분은 본문 전체를 한 번 보내고 요약 · 결정사항 · 할 일을 구조화 출력으로 받는다. 프롬프트 규칙은 spec 의 요구를 그대로 쓴다: 없는 사실을 보태지 않고, 합의된 것만 결정으로 넣고, 담당자나 기한이 드러난 것만 할 일로 넣는다. 할 일의 담당자는 팀 멤버 이름과 대조하고 못 찾으면 미정이다.

### D5. 저장 모양은 문서대로 줄바꿈 텍스트다
`meetings.summary` · `meetings.decisions` 는 줄바꿈 TEXT 이고, 화면이 줄 단위로 끊어 번호를 붙인다(`decision_count` 는 빈 줄을 뺀 수). 할 일은 `todos` 행으로 풀어 저장한다. 별도 JSON 컬럼을 만들지 않는다.

### D6. 업로드는 Vercel Blob 에 직접 올리고 서버는 주소로 받아쓴다
Vercel 함수의 요청 본문 한도(약 4.5MB)가 25MB 와 맞지 않아, 배포 환경에서는 브라우저가 Blob 에 파일을 올리고 서버는 그 주소를 받아 받아쓰기만 한다. 파일은 보관하지 않고 본문 텍스트만 돌려준다. `/api/upload` 는 한 경로로 유지해 API 수 26개를 지킨다. 로컬에는 Blob 이 없으므로 서버가 파일을 직접 받는다. 두 길 모두 형식(415) · 용량(413)을 같은 기준으로 판정한다.
- 대안 1: 상한을 4MB 로 낮춘다. 25MB 가 ACME 제약이라 택하지 않았다
- 대안 2: 로컬과 배포 상한을 다르게 둔다. 환경마다 동작이 달라져 택하지 않았다

### D7. 기한 지남은 화면의 순수 함수 하나로 판정한다
`isLate(dueText, status, metAt)` 하나만 둔다. `어제` · `지난 주` · `지난 달` 포함이면 지남, `N월 N일` 은 `met_at` 의 연도로 오늘과 비교하고, 그 외(`미정` · `다음 주 금요일` · `이번 주 안` 등)는 판정하지 않는다. 완료는 항상 제외한다. 서버는 `due_text` 를 비교하지 않는다.

### D8. DB 와 환경 분기
`DATABASE_URL` 이 있으면 Neon Postgres, 없으면 `meetingnote.db`(SQLite, git 제외). 같은 SQLAlchemy 모델 한 벌로 양쪽을 쓴다. 시각은 UTC 로 저장하고 화면이 현지 시간으로 바꾼다.

### D9. 환경변수
로컬 `.env` 와 `.env.example` 은 `GEMINI_API_KEY` · `GEMINI_MODEL` 두 줄뿐이다. `JWT_SECRET` · `DATABASE_URL` · Blob 토큰은 배포 환경변수(Vercel)에만 둔다. `JWT_SECRET` 이 없을 때 로컬 기본값은 코드에 두되 배포에서는 반드시 환경변수로 덮는다. `.env` 는 `.gitignore` 에 있고 저장소는 공개이므로 키를 코드나 문서에 적지 않는다.

## Risks / Trade-offs

- [Blob 직접 업로드가 Python 서버와 번들러 없는 Vanilla JS 프런트에 어떻게 맞는지 미확인] → 구현 첫 작업에서 짧은 검증을 하고, 안 맞으면 업로드 방식을 사용자에게 다시 묻는다
- [배포 환경에서만 쓰는 업로드 길은 로컬에서 시험할 수 없다] → 형식 · 용량 판정을 한 함수로 모아 두 길이 공유하고, 배포 후 25MB 파일로 한 번 확인한다
- [받아쓰기 60초 제한이 Vercel 함수 실행 시간과 맞는지 미확인] → 플랜 한도를 구현 때 확인하고 모자라면 사용자에게 알린다
- [Gemini 호출 실패 · 시간 초과] → 회의록은 본문과 함께 저장하고 세 항목은 비우며 공통 알림을 띄운다
- [기한 글자가 자유 문장이라 `다음 주 금요일` 등은 지남 판정이 안 된다] → 의도된 한계다. 해를 넘기는 `N월 N일` 도 판정하지 않는다
- [로컬 SQLite 와 Neon Postgres 의 동작 차이] → 방언 의존 쿼리를 쓰지 않고 ORM 만 쓴다
- [bcrypt 비용 때문에 가입과 로그인이 250ms 를 넘길 수 있다] → 해시 비용 인자를 측정으로 정한다

## Open Questions

답이 나중에 와도 스펙과 작업 분해가 바뀌지 않는 것들이다.

- 확정 HTML 이 디자인 규칙과 어긋난 곳은 그대로 구현한다(proposal 결정 4). 어긋난 곳: `detail.html` 의 수정 · 삭제 · 삭제 확인 버튼 `h-10`, `team.html` 의 이름 저장 버튼 `h-9` 와 파란 채움, `detail.html` · `todos.html` 의 담당자 select 높이. 디자인 쪽에서 `publish/` 를 고치면 다시 가져온다
- `GET /api/auth/me` 응답에 `team_id` · `team_name` 을 더했다. 스토리보드 매핑표(I-01)는 meetings · todos 화면이 `auth/me` 외에 팀 id 를 얻는 호출을 두지 않아, 팀 API 경로의 `{id}` 와 헤더 팀 이름의 출처가 문서에 없었다. 문서에 없는 필드를 더한 것이므로 사용자 확인이 필요하다 (사용자가 요청한 매핑표 준수를 우선했다)
- 비밀번호 변경은 프로그램정의 7-4 대로 현재 비밀번호를 받는다(사용자 확정). 확정 `profile.html` 에는 그 입력칸이 없으므로 구현 때 `window.UI.label` · `window.UI.input` 만 써서 칸 하나를 더한다. 오류 코드는 문서에 있는 `UNAUTHORIZED`(401)를 쓴다. 이 한 칸이 HTML 을 그대로 구현한다는 원칙의 유일한 예외다
- 프로그램정의 7-5 의 「키는 `GEMINI_*` 둘뿐」은 로컬 `.env` 에만 적용되는 것으로 읽었다. 배포 환경변수에는 Blob 토큰이 더해진다
- `login.html` 주석의 세션 만료 ID `H-01` 은 스토리보드의 `B-03` 이 맞다. `meetings.html` · `detail.html` · `todos.html` · `team.html` 주석의 상태 번호 범위도 스토리보드(C-01~11 · D-01~13 · E-01~12 · F-01~08)보다 좁다. 구현에 옮길 때 주석은 스토리보드 번호로 고친다
- 회의록을 지울 때 딸린 댓글을 어떻게 할지 문서에 없다. 외래키 연쇄 삭제로 함께 지우는 것으로 구현한다
